# 本地行情、仓位与风险

在本机运行的本地模拟交易引擎：一个账户、多个合约，现金与持仓以整数最小单位记账。行情由调用方逐笔推送，成交由调用方逐笔提交，系统不自动撮合。

## 基线

`Ready()` 始终返回 `true`，表示包可以加载。

## 使用

```bash
go test ./...
```

### 账户与合约

```go
acc, err := book.NewAccount(1_000_000) // 初始现金，必须非负
acc.SetPositionLimit("BTC", 10)       // 每个合约须先设置非负最大持仓量
acc.AddQuote("BTC", 1, 100, 50000)    // 序号从 1 开始，价格为正整数
```

### 行情

- 报价包含序号、模拟时刻、价格；只有连续序号才能推进为最新报价。
- 跨号报价先等待，补齐后依次生效。
- 重复序号内容一致不产生新事件；内容不同报错并保留原值。
- 尚无有效报价时拒绝下单；行情出现缺口时拒绝新买单，卖单、撤单和已有订单的成交仍可处理。

### 下单

```go
o, err := acc.PlaceOrder("BTC", book.Buy, 50000, 2)  // 限价 50000，买 2 手
```

- 价格、数量必须为正整数；只允许先买后卖，不借款、不做空。
- 买单按 `限价 × 数量` 冻结现金；卖单冻结可卖持仓。资金或可卖数量不足则拒绝。
- 订单状态：`OrderRejected` / `OrderPending` / `OrderPartialFilled` / `OrderFilled` / `OrderCancelled`。
- 错误输入（非法方向、价格或数量非正）返回 error 且不产生任何记录；业务条件不满足返回被拒绝的订单并说明原因。

### 成交（调用方提交）

```go
f, err := acc.SubmitFill(1001, o.ID, 1, 49900) // 成交编号、订单号、数量、价格
```

- 允许部分成交：买入价不得高于限价，卖出价不得低于限价。
- 买入按实际成交金额扣现金，限价与成交价的差额立即释放；卖出增加现金并扣持仓。
- 成交量超过剩余量、订单不存在或已撤销时整笔拒绝，资金与持仓不变。
- 同一成交编号相同内容重复提交返回原结果，不新增事件；不同内容明确报错。被拒绝的成交不占用编号，修正后仍可提交。

### 撤单

```go
acc.CancelOrder(o.ID)
```

- 只释放未成交部分，已成交部分保留；全部成交的订单不能撤销。

### 持仓限额

- 已持仓加所有买单剩余量不得超过限额；未成交卖单不抵消占用。
- 降低限额时立即从最后接受的买单开始，取消该单全部剩余量，直到满足新限额。
- 若已有持仓本身超限，撤掉全部未成交买单并拒绝后续买单，仍允许卖出，不自动平仓。
- 释放现金与持仓额度在同一操作内完成。

### 查询

| 方法 | 含义 |
| --- | --- |
| `CashBalance()` | 现金余额 |
| `AvailableCash()` | 可用现金（余额 − 占用） |
| `FrozenCash()` | 占用现金（未成交买单按限价冻结的金额） |
| `Position(contract)` | 持仓数量 |
| `Sellable(contract)` | 可卖数量（持仓 − 未成交卖单冻结量） |
| `Order(id)` / `Orders()` | 订单记录（含拒绝、待成交、部分成交、全部成交、撤销） |
| `Fills(orderID)` | 成交记录 |
| `LatestQuote(contract)` | 最新有效报价 |
| `PositionLimit(contract)` | 持仓限额 |

### 记录留痕

接受、拒绝、成交和撤销记录都保存当时可用的报价序号、时刻、价格及持仓限额；缺报价时明确为空（`Quote == nil`）。拒绝和限额触发的撤销都说明具体原因。后续报价或限额变化不会改写已有记录。

## 约束

- 不借款、不做空、不自动撮合。
- 价格、数量、现金均为整数最小单位。
- 所有方法并发安全（`sync.Mutex`），返回的订单/报价均为副本。
